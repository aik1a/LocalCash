## Método reproducible

El workflow hace checkout de `github.sha`, verifica igualdad con `git rev-parse HEAD`, reproduce el atlas a partir del extracto OSM versionado y compara sus bytes. Ejecuta:

```sh
python tools/maps/verify_atlas.py
python tools/maps/generate_offline_tiles.py --output "$RUNNER_TEMP/atlas/santiago_centro.zip" --preview evidence/atlas-preview-z16.png
cmp app/src/main/assets/maps/santiago_centro.zip "$RUNNER_TEMP/atlas/santiago_centro.zip"
bash tests/domain-checks.sh
bash gradlew --no-daemon --console=plain :app:assembleDebug :app:assembleDebugAndroidTest
```

Se registran código de salida Gradle, SHA y SHA256 de ambos APK. Cada job crea su AVD descartable sin restaurar snapshots; comprueba que no existe paquete LocalCash y usa `adb install` sin `-r`. Los fixtures son destructivos y solo se ejecutan sobre ese AVD. No ejecutar sobre datos reales.

Después de instalar app e instrumentación:

```sh
python tests/biometric-emulator.py prepare
python tests/biometric-emulator.py enroll
python tests/biometric-emulator.py security
python tests/maps-emulator.py
python tests/biometric-regression-dispatch.py <24|36>
```

El dispatcher existente ejecuta el recorrido financiero/GPS completo únicamente en API36. API24 repite seguridad biométrica, SQLite del fixture y mapa offline. Los flujos de UI son automatizados mediante instrumentación/accesibilidad/ADB; no se presentan como recorridos manuales. La huella se enrola en ajustes Android y se suministra al sensor del emulador; no se modifica la sesión productiva ni se invocan callbacks falsos.

El primer mapa exige `Active default network: none`, `ConnectivityManager` desconectado, ausencia de permiso INTERNET y ausencia del atlas privado antes de copiar desde el APK. No equivale a afirmar que todo el AVD estuvo desconectado desde su arranque. Se mantiene `FLAG_SECURE`; los PNG del proveedor y render MapView autenticado son evidencia alternativa.
