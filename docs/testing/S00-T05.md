# Validación S00-T05

## Ejecución reproducible
bash tests/domain-checks.sh; bash gradlew --no-daemon --console=plain :app:assembleDebug :app:assembleDebugAndroidTest. Workflow .github/workflows/s00-t05-build.yml ejecuta el SHA recibido, registra retorno, hash del APK y artefacto completo.

Emulador API36: FlowChecks (cuentas), mode purchases (v1→v3, contactos/compras), mode shared (v2→v3, deudas). Los fixtures son destructivos únicamente sobre la BD del emulador desechable; no ejecutar contra instalaciones con datos de usuario. shared requiere el resultado del flujo purchases.

## Escenarios
- Equitativo 100,01 entre IDs 1/2/3: 33,34+33,34+33,33, aunque la selección se haga en otro orden.
- Personalizado 20+30+50=100; negativo, suma desigual, formato inválido y overflow rechazados.
- Contacto asociado a compra no seleccionado automáticamente. Compra planificada rechazada.
- Dos contactos mínimos; repetidos/inexistentes rechazados; cuota 0 permitida.
- Monto máximo long y barrido de totales 0..299 con 2..10 participantes: conservación y diferencia <=1 centésima.
- Fixture v2 con snapshot de cada fila de cuentas, movimientos, contactos, compras y detalles idéntico tras migrar a v3.
- Integridad FK/PK/CHECK y rollback inducido del segundo insert; revalidación de total persistido.
- Compra ya repartida no admite otro conjunto de participantes. Consulta desde detalle tras volver.
- force-stop y relanzamiento: dos repartos y saldo anterior visibles; XML y capturas conservados.

## Evidencia
Consultar docs/handoffs/S00-T05-coder.md para SHA funcional, run, resultado real y APK. Este documento describe escenarios; no constituye un resultado PASS por sí solo. No prueba actualización de APK T04→T05 con la misma firma ni dispositivo físico (T07).
